name: Approved Boardwork direction
description: Records the validated product direction that later infrastructure work should preserve.

Preserve Boardwork’s current core workflow and restrained professional visual direction when adding later capabilities. Favor focused refinements over redesigns or added feature breadth.

**Why:** The user explicitly confirmed that the core experience and overall direction work well, then requested persistence without a redesign.

**How to apply:** Add durability or intelligence without restructuring the class-to-board-to-present loop unless classroom testing identifies a concrete usability problem.

Keep class data separated into three layers: durable class profile, periodically changing instructional context, and per-activity boardwork context. Treat class color only as subtle organizational metadata.

**Why:** Teachers should not re-enter stable or periodic context during daily generation, and a class identifier should not become a presentation theme.

**How to apply:** Preserve these boundaries as persistence evolves and when later AI inputs are assembled; do not move current units into permanent profile settings or apply class colors to generated boards.

Saved Context is an optional reusable input within that workflow, not a reason to add a teacher-account migration or a curriculum-management dashboard. “All classes” means this shared installation, not school-wide sharing.

**Why:** The user explicitly chose to keep the existing shared-app model and clear daily selections on class changes, rather than introduce private teacher libraries or remembered selections.

**How to apply:** Keep later context improvements narrow. Revisit ownership or persistent selection only when separately requested; don't infer them from authentication being present.

Reserve the strong primary fill for Create board in the main setup area; use neutral selected surfaces for setup choices.

**Why:** The user found dark-blue Duration and Technology selections competed with Create board and explicitly requested that only the creation action carry that visual weight in this area.

**How to apply:** Keep selections recognizable through neutral fill, text, and border contrast, with separate keyboard focus. This is a setup-area hierarchy rule, not a ban on primary Save/Create actions inside dialogs.
